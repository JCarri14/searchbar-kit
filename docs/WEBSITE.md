# SearchbarKit website v3.1

The public site lives in `apps/web`. It keeps the existing React SearchBar and the full Builder, Theme and Export capabilities, but presents them in a full-height canvas. **Personalizar** is the only always-visible editing action. The Simple / Con filtros / Avanzada switcher remains centered at the top of the canvas. Editor and inspector are floating overlays, closed by default.

The navigation has three views:

- **Componente** (`/es/`, `/en/`): full-height canvas, variants, customizer and live SearchBar.
- **Demo** (`/es/demo/`, `/en/demo/`): one live SearchBar with a small local manga dataset and reactive results. No gallery card grid.
- **Guía** (`/es/docs/`, `/en/docs/`): integration docs, with the same interactive SearchBar at the top.

`Site` owns the `BuilderProject` and `SearchQuery` state and passes both to each view, so moving between Component, Demo and Guide preserves the current configuration, theme, selected filters and search text. The example results adapter in Demo deliberately knows only the local sample data; arbitrary user-defined fields require a real host application's adapter.

The separate `apps/*-demo` applications remain independent integration examples.

Routing is history-based on the client, with static HTML entrypoints generated by `scripts/prerender-pages.mjs` after Vite builds to support direct visits to GitHub Pages routes. The pages are not server-side rendered. Deploy uses `VITE_BASE_PATH` for project/repo base paths.

The shadcn-compatible registry remains generated from source via `scripts/sync-registry.mjs` and `scripts/build-registry.mjs`. The registry smoke test checks file graph and the CSS entrypoint; installing with the CLI in a clean external project still requires validation with dependencies available.
